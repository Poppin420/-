# Φωνητικός Βοηθός Επιχείρησης

Mobile-first εφαρμογή (PWA) για Έλληνες ελεύθερους επαγγελματίες και μικρές επιχειρήσεις: μιλάς ελληνικά, η
εφαρμογή καταλαβαίνει μία ή περισσότερες εντολές, δείχνει κάρτα επιβεβαίωσης για την καθεμία και δεν εκτελεί
τίποτα χωρίς ρητή επιβεβαίωση.

> ⚠️ **Οι φορολογικοί κανόνες πρέπει να επαληθευτούν από λογιστή πριν από πραγματική χρήση.** Δείτε την ενότητα
> [Φορολογικές παραδοχές](#φορολογικές-παραδοχές-για-έλεγχο-από-λογιστή).

## Κατάσταση φάσεων

| Φάση | Περιεχόμενο | Κατάσταση |
|---|---|---|
| (α) | Φωνή → μεταγραφή → ανάλυση → κάρτες επιβεβαίωσης | Υλοποιημένη. Unit tests περνούν. **Δεν έχει δοκιμαστεί ακόμη με πραγματικό Groq** (βλ. παρακάτω). |
| (β) | Ημερολόγιο, διπλοκρατήσεις, λογαριασμοί χρηστών, Google Calendar | Δεν έχει ξεκινήσει |
| (γ) | Προφίλ επιχείρησης, υπολογισμοί, myDATA sandbox, πάροχος ηλεκτρονικής τιμολόγησης για B2B | Δεν έχει ξεκινήσει |
| (δ) | Πραγματικό περιβάλλον ΑΑΔΕ | Δεν έχει ξεκινήσει |

Τι έχει επαληθευτεί στη φάση (α):

- 173 unit tests (parsers αριθμών/ποσών/ωρών/ημερομηνιών, 35 σενάρια ελληνικών εντολών, server, Groq clients με
  προσομοιωμένο δίκτυο).
- Η ροή στον browser (Chromium, οθόνη κινητού) με προσομοιωμένο API: ηχογράφηση → κάρτες → απαντήσεις → επιβεβαίωση.

Τι **δεν** έχει επαληθευτεί:

- Πραγματικές κλήσεις σε Groq Whisper και Groq LLM. Τρέξτε `GROQ_API_KEY=... npm run eval:llm` και δείτε
  [Αξιολόγηση LLM](#αξιολόγηση-llm).
- Ηχογράφηση σε πραγματικές συσκευές iOS/Android.
- Τα όρια χρόνου, μεγέθους και rate limiting των Netlify Functions στο δικό σας πλάνο.

## Αρχιτεκτονική

```
web/                      React PWA (Vite)
netlify/functions/        Thin HTTP wrappers (Netlify Functions v2)
src/
  transcription/          Groq Whisper client (whisper-large-v3, language=el)
  intent-parsing/
    schema.ts             Strict JSON schema for LLM output (zod)
    prompt.ts             Extraction prompt: verbatim spans only, no calculations
    llmProvider.ts        IntentLLM interface + Groq implementation (swappable)
    greekNumbers.ts       "εκατόν είκοσι πέντε" -> 125, no floating point
    greekMoney.ts         "ογδόντα ευρώ και πενήντα λεπτά" -> "80.50"
    greekTime.ts          "πέντε το απόγευμα" -> 17:00, "στις 5" -> ambiguous
    greekDate.ts          "την Παρασκευή", "25/10", Europe/Athens
    resolve.ts            LLM spans -> cards, questions, assumptions
  server/handlers.ts      Request handling, access check, error mapping
  shared/afm.ts           Greek tax number (ΑΦΜ) check digit
tests/                    Vitest unit tests + Greek command corpus
scripts/eval-llm.ts       Corpus against the real LLM
```

### Βασικός κανόνας: το LLM δεν υπολογίζει τίποτα

1. Το LLM χωρίζει την εντολή σε ενέργειες και **αντιγράφει αυτούσια** κομμάτια του κειμένου (π.χ.
   `time_text: "πέντε το απόγευμα"`). Δεν μετατρέπει, δεν υπολογίζει, δεν συμπληρώνει.
2. Κάθε κομμάτι πρέπει να υπάρχει στη μεταγραφή. Αν το LLM «εφεύρει» όνομα ή ποσό, η κάρτα ρωτάει.
3. Ημερομηνίες, ώρες, ποσά και ποσότητες τα ερμηνεύει ντετερμινιστικός κώδικας.
4. Ό,τι λείπει ή είναι διφορούμενο γίνεται ερώτηση: «στις 5» (πρωί ή απόγευμα;), «την επόμενη Παρασκευή»,
   «περίπου 100 ευρώ», ποσό με ή χωρίς ΦΠΑ, τιμή ανά μονάδα ή συνολική.
5. Στο LLM στέλνεται μόνο η μεταγραφή. Δεν στέλνονται ημερομηνία, πελατολόγιο, ΑΦΜ ή κλειδιά.

### Γιατί αυτές οι τεχνικές επιλογές

- **PWA αντί για native app:** δεν χρειάζεται app store, ενημερώνεται αμέσως και η ηχογράφηση δουλεύει σε
  Android και iOS Safari 14.3+.
- **TypeScript σε Netlify Functions:** η φιλοξενία είναι στο Netlify, που δεν τρέχει Python στις Functions.
  Frontend και backend μοιράζονται τους ίδιους parsers, οπότε οι απαντήσεις στις κάρτες ερμηνεύονται με τον ίδιο
  κώδικα.
- **Groq** για μεταγραφή και LLM. Ο πάροχος LLM αλλάζει υλοποιώντας το `IntentLLM`.

## Εγκατάσταση

Απαιτείται Node.js 20+.

```bash
npm install
npm test           # unit tests
npm run typecheck
npm run build
```

Τοπική εκτέλεση με τις Functions:

```bash
npm install -g netlify-cli
cp .env.example .env    # συμπληρώστε τα κλειδιά
netlify dev
```

## Ρύθμιση κλειδιών

| Μεταβλητή | Πού | Σημειώσεις |
|---|---|---|
| `GROQ_API_KEY` | Μόνο στον server | Από https://console.groq.com. Δεν φτάνει ποτέ στον browser και δεν καταγράφεται σε logs. |
| `APP_ACCESS_TOKEN` | Μόνο στον server | Προσωρινός κοινός κωδικός πρόσβασης για τη φάση (α), τουλάχιστον 16 χαρακτήρες. Τη θέση του παίρνουν λογαριασμοί χρηστών στη φάση (β). |
| `GROQ_LLM_MODEL` | Προαιρετικό | Προεπιλογή: `llama-3.3-70b-versatile`. Ελέγξτε ότι το μοντέλο είναι διαθέσιμο στο Groq. |

Στο Netlify οι μεταβλητές μπαίνουν στο *Site configuration → Environment variables* και δηλώνονται ως secret.
Αν λείπει κάποιο κλειδί, ο server αρνείται όλα τα αιτήματα (503).

Τα διαπιστευτήρια myDATA (όνομα χρήστη και subscription key) **δεν** είναι μεταβλητές περιβάλλοντος: κάθε
χρήστης θα τα εισάγει ο ίδιος στη φάση (γ) και θα αποθηκεύονται κρυπτογραφημένα (AES-256-GCM) ανά χρήστη.

## Αξιολόγηση LLM

```bash
GROQ_API_KEY=... npm run eval:llm
```

Στέλνει τις 35 εντολές του `tests/fixtures/commands.ts` στο πραγματικό μοντέλο και ελέγχει ότι οι κάρτες
βγαίνουν ίδιες με τα unit tests. Επειδή η έξοδος ενός LLM μπορεί να αλλάξει από έκδοση σε έκδοση, πρόκειται για
αξιολόγηση και όχι για unit test.

## Ασφάλεια και απόρρητο (φάση α)

- Ο ήχος μένει μόνο στη μνήμη κατά τη μεταγραφή. Δεν γράφεται σε δίσκο ούτε σε logs.
- Τα logs καταγράφουν μόνο το στάδιο, τον τύπο σφάλματος και τον κωδικό HTTP. Δεν καταγράφουν κείμενο, ήχο ή
  κλειδιά.
- HTTPS παντού (Netlify και HSTS), αυστηρό Content-Security-Policy, μικρόφωνο μόνο για τον ίδιο τον ιστότοπο.
- Όριο αιτημάτων στις Functions (`rateLimit` στο config): ελέγξτε ότι υποστηρίζεται από το πλάνο σας.
- Όριο 60″ ηχογράφησης και 5 MB ήχου.
- TODO (φάση β): λογαριασμοί χρηστών, πολιτική απορρήτου, εξαγωγή και διαγραφή δεδομένων (GDPR), επιλογή
  αποθήκευσης ηχητικών.

- Πρόσβαση στο `aade.gr` από το περιβάλλον ανάπτυξης, για ανάγνωση της προδιαγραφής και των XSD (φάση γ).
